1. Các thành phần cơ bản của Android (Android Components)
Nền tảng Android gồm 4 thành phần cốt lõi:

Activity: Đại diện cho một màn hình giao diện người dùng (UI) có tương tác.

Service: Thực hiện các tác vụ chạy ngầm không cần giao diện người dùng.

Broadcast Receiver: Lắng nghe và phản hồi các thông điệp/sự kiện từ hệ thống hoặc các ứng dụng khác.

Content Provider: Quản lý và chia sẻ dữ liệu giữa các ứng dụng một cách an toàn.

Ví dụ mã nguồn (Activity):
Kotlin
import android.os.Bundle
import android.widget.Button
import android.widget.Toast
import androidx.appcompat.app.AppCompatActivity

class MainActivity : AppCompatActivity() {
    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        
        val button = Button(this).apply {
            text = "Click me"
            setOnClickListener {
                Toast.makeText(context, "Hello World!", Toast.LENGTH_SHORT).show()
            }
        }
        
        setContentView(button)
    }
}
2. Cấu trúc bộ khung của dự án Android Studio
Một cấu trúc dự án Android chuẩn bao gồm các thư mục và tệp chính:

manifests/ (AndroidManifest.xml): Khai báo cấu hình ứng dụng, tên app, icon, quyền truy cập (permissions) và danh sách các thành phần (Activity, Service,...).

java/ (hoặc kotlin/): Chứa toàn bộ mã nguồn xử lý logic của ứng dụng.

res/ (Resources): Chứa các tài nguyên không phải mã nguồn:

drawable/: Hình ảnh, icon, đồ họa vector.

layout/: Các file XML định nghĩa giao diện màn hình.

values/: Các file chứa chuỗi (strings.xml), màu sắc (colors.xml), theme/style (themes.xml).

Gradle Scripts/: Quản lý cấu hình build, phiên bản SDK và các thư viện phụ thuộc (build.gradle.kts).

3. Vòng đời của một ứng dụng Android (App Lifecycle)
Vòng đời của một Activity bao gồm các trạng thái chính:

Created: Activity bắt đầu được khởi tạo và cấp phát bộ nhớ.

Started: Activity xuất hiện trên màn hình nhưng chưa thể tương tác.

Resumed: Activity hiển thị hoàn toàn trên màn hình và sẵn sàng nhận tương tác từ người dùng.

Paused: Activity bị che khuất một phần (ví dụ khi xuất hiện dialog hoặc có cuộc gọi đến).

Stopped: Activity bị che khuất hoàn toàn khi chuyển sang ứng dụng khác hoặc về màn hình chính.

Destroyed: Activity bị hệ thống hủy hoàn toàn khỏi bộ nhớ.

4. Kiến trúc Android và các Design Pattern phổ biến
Kiến trúc hệ điều hành Android gồm 4 tầng chính từ thấp đến cao:

Linux Kernel: Quản lý phần cứng, bộ nhớ, tiến trình và bảo mật.

Libraries & Android Runtime (ART): Các thư viện C/C++ hệ thống và môi trường thực thi ứng dụng.

Application Framework: Cung cấp các API hệ thống cho ứng dụng sử dụng.

Applications: Tầng ứng dụng người dùng.

Các Design Pattern phổ biến:
MVC (Model - View - Controller): Tách biệt dữ liệu (Model), giao diện (View) và bộ điều khiển (Controller).

MVP (Model - View - Presenter): Presenter làm trung gian nhận sự kiện từ View, xử lý dữ liệu với Model và cập nhật lại View.

MVVM (Model - View - ViewModel): ViewModel quản lý dữ liệu cho View thông qua cơ chế liên kết dữ liệu (Data Binding/StateFlow), giúp tách biệt logic giao diện và dễ dàng mở rộng, bảo trì.
